# Electron App-Shell Framework — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Build a reusable Electron + Vite + React + TypeScript app-shell framework (a _platform_, not an app) with dark/light theming, a collapsible sidebar (left) + icon rail or collapsible panel (right), a top tab navigation bar, a main dashboard view, and a settings page — all designed so future apps (chat app, dashboards, tools) are created by _dropping in a page_, not rewriting the shell.

**Architecture:**

- **Processes:** Electron main process (window lifecycle, app shell chrome, IPC, safe local storage) + Vite dev server in dev / static files in prod (electron-vite standard layout).
- **Renderer:** React 18 + TypeScript. The shell is a layout engine (`AppShell`) + a page registry. Pages are registered by id/icon/label and the top tabs + sidebar render from that registry — adding "a chat app" means adding one page module + one registry entry.
- **Styling:** Tailwind CSS v4 with CSS-variable theming → light/dark class strategy, persists via Electron `safeStorage`-encrypted JSON config file. UI primitives: shadcn/ui (button, card, input, switch, tabs, scroll-area, tooltip, separator, avatar, badge, dropdown-menu, dialog, sheet).
- **Backend:** none in v1 — the framework exposes an IPC contract (`window.api`) and a `bridge.ts` stub so a backend can be wired later without touching the shell.

**Tech Stack:** Electron 33, electron-vite 2, Vite 6, React 18, TypeScript 5, Tailwind CSS v4, shadcn/ui, Radix primitives, lucide-react icons, electron-builder (packaging later).

```ts
import { app, BrowserWindow, shell } from 'electron'
import { join } from 'node:path'

function createWindow(): void {
  const win = new BrowserWindow({
    width: 1440,
    height: 900,
    minWidth: 960,
    minHeight: 600,
    show: false,
    autoHideMenuBar: true,
    titleBarStyle: process.platform === 'darwin' ? 'hiddenInset' : 'default',
    backgroundColor: '#0b0f14',
    webPreferences: {
      preload: join(__dirname, '../preload/index.js'),
      sandbox: true,
      contextIsolation: true
    }
  })
  win.on('ready-to-show', () => win.show())
  win.webContents.setWindowOpenHandler(({ url }) => {
    shell.openExternal(url)
    return { action: 'deny' }
  })
  if (process.env.ELECTRON_RENDERER_URL) win.loadURL(process.env.ELECTRON_RENDERER_URL)
  else win.loadFile(join(__dirname, '../renderer/index.html'))
}
app.whenReady().then(() => {
  createWindow()
  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow()
  })
})
app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit()
})
```

**Step 4:** `src/renderer/index.html` loading `/src/main.tsx`; `main.tsx` renders `<App/>` under `<React.StrictMode>`.

## Task 1: Theme system (dark/light core)

**Objective:** Full light/dark theming driven by CSS variables + a `ThemeProvider` that persists choice.

**Files:**

- Create: `src/renderer/src/styles/theme.css` (CSS vars for both themes incl. shadcn tokens: background, foreground, card, muted, accent, border, sidebars, tab bar)
- Create: `src/renderer/src/lib/theme.ts` (type `Theme = 'dark' | 'light'`, toggle logic, `data-theme` attribute management)
- Create: `src/renderer/src/components/theme/ThemeProvider.tsx` (React context: `theme`, `setTheme`, `toggleTheme`; applies `data-theme` on `<html>`; default dark)
- Modify: `src/renderer/src/main.tsx` (wrap `<App/>` in `ThemeProvider`)
- Create: `src/renderer/src/components/ui/theme-toggle.tsx` (shadcn button + Sun/Moon lucide icons)

**Key design decisions:**

- Persistence is NOT localStorage — it goes through IPC `theme:set` into an encrypted config file (Task 5). In this task, provider reads initial value from `window.api?.config.get('theme') ?? 'dark'` with a localStorage fallback so the UI works before IPC is wired.

**Verify:** Toggle flips the whole app dark↔light; choice survives app restart (via fallback until Task 5).

## Task 2: Layout engine — AppShell

**Objective:** The reusable layout: left sidebar (icons, collapsible), top tab bar, right sidebar (collapsible), content area. This is THE core reusable piece.

**Files:**

- Create: `src/renderer/src/components/shell/AppShell.tsx` — grid layout: `[sidebar-left | main-column]`, main column = `[top-tab-bar / content]`, optional right pane
- Create: `src/renderer/src/components/shell/Sidebar.tsx` (left) — icon rail (collapsed) / icon + label (expanded, 220px), collapse chevron, bottom user/status block placeholder
- Create: `src/renderer/src/components/shell/TopBar.tsx` — tabs row (from registry) + right cluster: theme toggle, settings gear, window controls placeholder
- Create: `src/renderer/src/components/shell/RightPanel.tsx` (right sidebar) — collapsible panel for inspector/detail/context panes (chat apps, dashboards all want a right pane); collapse with chevron
- Create: `src/renderer/src/components/shell/ResizeHandle.tsx` — draggable divider for left sidebar width (nice-to-have, simple pointer-event logic)
- Create: `src/renderer/src/lib/ui-state.ts` — lightweight UI state (sidebar collapsed, right panel open) via zustand

**Layout contract (v1):**

- Left sidebar: 64px collapsed / 220px expanded; icons-only when collapsed with tooltips.
- Top bar: 48px; tabs scroll horizontally when overflowing.
- Right panel: 0px (hidden) / 300px; toggled per-page via registry entry `rightPanel?: ReactNode`.
- Content: fills remaining space, `overflow: auto`, per-page scroll.

**Verify:** All four regions render; both sidebars collapse/expand; resize handle works; layout survives theme switch.

## Task 5: Persistence & IPC contract

**Objective:** Secure config storage + typed IPC bridge. The contract future apps code against.

**Files:**

- Create: `src/main/config-store.ts` — JSON file at `app.getPath('userData')/config.json`, values encrypted with `safeStorage.encryptString` (falls back to plaintext where safeStorage is unavailable); `get/set` channel handlers
- Create: `src/main/ipc.ts` — registers `config:get`, `config:set`, `theme:set`, `app:getVersion`, plus a `ping` health check
- Create: `src/preload/index.ts` — `contextBridge.exposeInMainWorld('api', { config: { get, set }, theme: { set }, app: { version } , ping })`, `contextIsolation` kept on
- Create: `src/renderer/src/types/api.d.ts` — the typed `window.api` contract
- Modify: `src/renderer/src/lib/theme.ts` + `SettingsPage` — real persistence through `window.api`

**Security defaults:** `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, IPC channel allowlist, no arbitrary path access from renderer.

**Verify:** Change theme → restart app → theme persists. `window.api.ping()` replies. Typecheck passes on both workspaces.

## Risks & notes

- **Tailwind v4 + electron-vite**: v4 uses the Vite plugin, no `tailwind.config.js` needed; if the shadcn CLI expects v3, hand-wire. Known friction point — handle in Task 1/4.
- **shadcn CLI inside electron-vite layout**: `components.json` paths must point at `src/renderer/src/...`; if CLI refuses, add components manually.
- **safeStorage on Linux**: needs a keyring; fallback to plaintext JSON behind a `useEncryption` flag — acceptable for v1 framework (dev machine is Windows).
- **Windows DevTools shortcut**: keep `Ctrl+Shift+I` devtools toggle in dev only (`!app.isPackaged`).
